# LifeOS Personal — release implementation handover
## Scope and authority
Goals, Insights and My Life only. Preserve Today, Track and the ongoing Plan implementation. Work on isolated Preview; never overwrite production data, signing keys or another agent's unmerged work. Inspect current branch and coordinate integration before editing. Original Goals and Insights references are supplied as images. My Life is a proposed design specification, not an approved original image. Example figures in all mockups are illustrative and sometimes inconsistent; calculate real values instead.
## Shared visual system
Dark navy canvas, slightly lighter navy cards, mint primary actions, muted blue secondary data, amber warnings and red overdue states. Match original references in hierarchy, density, icons, rounded borders and typography. Use existing theme tokens and equivalent accessible light theme. Compact headers, meaningful charts, progressive disclosure, no duplicate headings, no technical JSON forms in primary flows. Keep six-section bottom navigation above system inset without covering controls; keyboard-aware sheets, scrollable content, accessible labels and touch targets. Test 360/393/412 CSS px widths and reduced-height keyboard viewport. Do not sacrifice readability to fit one screen.
## Goals
Overview: weekly progress ring, on-track/at-risk/paused counts, active goal cards with category icon, target, actual progress, status, next deadline, and detail link; milestones summary. Compute status from elapsed period and actual target; no invented percentages. Create/edit: title, category/activity link, measurable target and unit (minutes, hours, sessions, pages, days, quantity), period, deadline, priority, recurrence, optional milestones and notes. Clarify weekly recurrence versus every N days; validate and persist; allow pause/resume/archive/delete with confirmation. Detail: evidence sessions, manual quantity entries, progress chart, milestones, edit and history. Improve: goal health, daily progress, evidence-based recommendations, suggested schedule changes with review/approval, recovery/reschedule and goal progress. Include two-week review and prior two-week comparison where data supports it. History: completed/archived/all filters, achievement trend, recent completed goals, month→period drill-down; preserve historical targets when editing current goals. Include optional goal review/calculation reference. Use actual records; distinguish manually confirmed progress from automatically matched sessions. Never double count overlapping minutes within a goal or count a timer as pages read.
## Insights
Live / History / Review navigation as reference. Live: week-at-a-glance, recorded total vs unique time vs overlap clearly distinguished, activity count, 7-day chart and concise takeaway. Activity insights: filters, category cards with duration, sessions, active days and trend; drill down to named activity, averages and individual records. History: weekly/monthly/custom range, recorded days, highest day, weekly average with explicit denominator, trend, expandable weeks/days. Day details: date navigation, recorded/unique/overlap totals, activity list with details. Review: Insights / Distractions / Next steps; evidence-based findings, editable/deletable distraction classifications, practical next steps and links to existing workflows. Data & reliability: confidence based on coverage, transparent calculation rules, privacy, prediction availability; no fabricated trends or confidence. Use raw interval math, local dates, overnight splitting and consistent definitions across Today/Track/Plan. Missing data is unknown, not zero behavior. No unsupported productivity or causal claims.
## My Life — proposed layout (not original visual reference)
Use same visual language as Goals and Insights. Main hub: compact header, summary of personal wellbeing records and 2-column module cards for Fitness, Nutrition, Habits, Friends & challenges; each opens dedicated screen with back navigation. Avoid a single long page of nested forms. Show recent progress and one primary action per module; keep advanced settings collapsed.
Fitness: weekly sessions, total and average duration, target progress, workout history grouped by week, body weight/body fat/measurements trends with dates and units, add/edit/delete measurements and workouts. Link completed Track sessions without duplicate timer entries. Nutrition: daily calories/protein/water against user-defined targets, meal cards and history, 7/14/30-day trends, add meal via manual entry or photo attachment if supported; label estimates and unknowns, never imply unlogged intake is zero. Water quick-add and optional reminders; edit/delete entries. Habits: today checklist, weekly consistency grid, streaks and history, create/edit sheet with frequency, start date, target/unit, optional activity matching and explicit auto-confirm opt-in; manual confirmation for pages or avoidance habits. Link Goals rather than duplicating progress. Friends & challenges: compact challenge cards, create/join via code, activity-specific targets (gym sessions, reading pages, Quran pages), personal progress and optional leaderboard. Real friend accounts, shared progress and notifications require secure authenticated backend, per-challenge consent, authorization and revocation; if unavailable, retain honest local-only mode, no fake live friends or ranks. Move legacy progress-card JSON import/export into advanced settings, preserve compatibility and privacy. Do not expose personal activity records by default.
## Release acceptance
Use realistic synthetic Preview fixtures covering populated/empty/error states, long names, overlapping/overnight sessions, completed/paused/archived goals, partial quantities, missing data and permissions. Verify create/edit/delete, navigation, filters, persistence after reload, data consistency, offline/reconnect behavior where supported, and no regressions in Today/Track/Plan. Test actual calculations independently of UI. Capture each screen in dark/light at mobile widths; compare against references and record deviations. Native Samsung safe area, keyboard, lock-screen notifications and timers require device verification; consolidate native changes into one signed Preview APK later. No production rollout until blockers resolved and user accepts. Report changed files, commit, tests, screenshot paths, deployment URL, remaining blockers and deferred features. Never label unverified work as release-ready.
