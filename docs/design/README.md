# Visual reference library

These folders distinguish **implementation captures** from the user's **approved design source images**. None of the captures here should be described as an approved mockup.

- `global/`: six-section navigation and device-inset evidence.
- `today/`: Concept A+ Overview, Timeline, Agenda and Review, plus details and gap sheets.
- `track/`: Concept A Live, History and Review.
- `plan/`, `goals/`, `insights/`, `my-life/`: current section captures and explicit missing-reference/approval status.

`current/` screenshots are generated from synthetic, local-only fixture data by `node scripts/capture-design-baselines.cjs`: 393×780 CSS pixels, Europe/Stockholm, fixed clock, all network requests intercepted. The separate high-volume timeline image is generated by the volume regression in `docs/TESTING.md`. No real account, Preview database or private activity records are used. They are browser captures, not native Android verification. The user's 25 November screenshots are current-device feedback, but the original image files and the original approved concept mockups are not stored here.

`today/before/` and `track/before/` contain synthetic captures from commit `5aa749b6173f4aa65c281672f0f785ef52cd2f02`; matching named images were regenerated from that archived revision with the same fixture. `393-tab-*` and `393-live.png` came from [GitHub Actions run 45652105939](https://github.com/Abdialin/lifeos-personal-fresh/actions/runs/45652105939), whose workflow uses isolated CI fixtures. They are historical implementation evidence, not approved design sources.

The original approved source images are missing for Today Overview, Timeline, Agenda and Review, and Track Live, History and Review. Request them from the user one subsection at a time. Future Plan, Goals, Insights and My Life design concepts require approval at the roadmap stage. Once a genuine reference is supplied, store an appropriately redacted/synthetic copy with provenance and update its comparison and approval status.
