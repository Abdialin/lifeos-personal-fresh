Reviewed 27 November 2026 from provider documentation. This is a research assessment, not a deployed service or a recovery guarantee. No provider account, project, database or credential was created or accessed, and no data was migrated. The user's approval is required before provisioning even a free resource or moving any data.

## Recommendation and required checks

Neon Free is the primary candidate for an isolated **test-data Preview**, with Supabase Free the secondary candidate. Render would continue hosting the existing application; only the proposed database would be external. This recommendation is subject to user approval and a real compatibility test. Its 1 GB allowance and six-hour recovery window are useful for a small Preview, but neither replaces a verified off-provider backup. At 0.25 CU, 100 CU-hours corresponds to 400 hours of active compute, not a full month of continuous use. The app opens PostgreSQL connections through Psycopg with a 10-second connection timeout; cold starts and monthly quota exhaustion must be tested before relying on it. Neon suspends idle compute and resumes it on demand, but the policy for long-term inactive project retention has not been verified for the user's prospective account. No current claims are made about availability, signup eligibility or actual user-account quotas.

The app retries queued sync changes, so continuous activity or retries could keep the database awake and consume compute allowance; actual usage has not been measured against Neon. The existing `/healthz` handler itself does not query the database, but that alone does not establish that the database will reliably become idle. Monitor the provider's usage and verify cold-start, retry and quota behavior with synthetic records after any approved setup.

For future growth, Neon offers paid usage-based plans and larger compute and security options; Supabase also offers paid plans and larger instances. Availability, pricing, backup retention, connection limits, geography, access restrictions and any card requirements must be reviewed at the time an upgrade is actually proposed. A free test database is not evidence of production-grade availability or recovery, and neither service should be used to move production or personal records as part of this Preview evaluation.

Both options use external network paths rather than the proposed private Render environment. Separate projects and credentials protect data boundaries, but do not provide the same network isolation as a private-only database. Verify TLS certificate and hostname validation, provider access policies, minimally scoped roles, secrets handling, regional placement and the user's isolation requirements before approval. Neon explains that [`sslmode=require` alone does not verify server identity](https://neon.com/blog/postgres-needs-better-connection-security-defaults) and that its connection strings use channel binding. The migration tool now requires `sslmode=verify-full` for remote targets and accepts the narrowly scoped `channel_binding=require` and `sslrootcert=system` parameters; offline URL tests verify the guard without opening a connection. The application connection, system trust store, driver support and Neon endpoint still require actual compatibility testing after approval. Do not remove identity, empty-target or TLS safeguards merely to make a provider connect.

Before any cutover: identify the authoritative Preview-only source; obtain and independently verify a recoverable backup; confirm what the backup omits; approve a new isolated provider project and any data movement; rehearse migration and rollback with synthetic data; verify database permissions, concurrent writes, off-provider dump/restore, restarts and an actual Preview redeployment; and preserve device/browser data throughout. The current server JSON backup contains workspace state only, not every server-side table. Render's current free SQLite service may already have spun down, so the existence and contents of its current or former records remain unknown. See [the storage runbook](PREVIEW_STORAGE_RUNBOOK.md).
